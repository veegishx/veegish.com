<p>A power outage occurred on 29/07/2026 at 05:24AM. Half a minute later power was restored and the server hosting my AdGuardhome instance, among other services, was back online. All 10 containers and VM, including AdGuard were online at the time, but there was 1 problem - internet was down. This is a note of the steps executed, should they need to be performed again.</p><h2>Confirm access without getting out of bed</h2><ul><li data-list-item-id="e80088352abd0a4fd05a1739df9e84d9c">While on data (because WIFI and LAN are presumably both down in these cases), make sure NetBird VPN is active</li><li data-list-item-id="e5427cc00dce06a78fd233d63d4deb285">Check if proxmox is accessible via direct IP access - 192.168.x.x</li><li data-list-item-id="e745eb30f2bdfc1cf1f05c41206c559dd">Check health of AdGuard container</li><li data-list-item-id="e848c4ac6cd2d06ee286ce8aa755857af">Realize it's time to get out of bed</li></ul><h2>Get out of bed and restore internet</h2><ul><li data-list-item-id="e88f898c9e1025372842b28e62f65f224">Connect PC with LAN and assign a static address<ul><li data-list-item-id="ec4fafea80355f8a71bbc011c811e1690"><pre><code class="language-text-x-trilium-auto">IP: 192.168.100.240
Subnet: 255.255.255.0
Gateway: 192.168.100.1
DNS1: 1.1.1.1
DNS2: 8.8.8.8</code></pre></li><li data-list-item-id="e131c84a518b5b59d616a21d5bb16cb69">Make sure to wake up properly so that it's 192.x.x.x and not 198.x.x.x.x like last time forcing me to waste 10 minutes panicking about being locked out of the router</li><li data-list-item-id="eb1e0156d791188f0f563b2cc1d4c3cef">flush the previous DNS config<ul><li data-list-item-id="e17e7afde712273a64f8775cb82aa032e"><pre><code class="language-text-x-trilium-auto">ipconfig /release
ipconfig /renew
ipconfig /flushdns</code></pre></li></ul></li></ul></li><li data-list-item-id="eb24fa9721fec327bf73f18ca2fc4e1eb">Connect to proxmox via it's static IP and ping the router<ul><li data-list-item-id="e9d7513cbd76954d0db25ed9685eb0ed8"><pre><code class="language-text-x-trilium-auto">ping 192.168.100.1</code></pre></li><li data-list-item-id="ee648bc769888397b7fdabd5579a7d580">if it's all good, we can rule out issues connecting to the gateway</li><li data-list-item-id="eeb46cc910f3d327cb8cbc2c625d25078">if not, good luck 🫡</li></ul></li><li data-list-item-id="eef4474028b5fa4f9bf58c4d757518246">Assuming our gateway connection is good, give the router back its job, login to <code spellcheck="false">192.168.100.1</code> and enable DHCP again so that everyone is the house is happy. Internet access should be restored, if not then turn off/on wifi on the devices to request new IP leases from the router.</li></ul><h2>Troubleshoot AdGuard container issues</h2><ul><li data-list-item-id="ed533b3f8254bda7e7a8d75d6e3161685">Check if AdGuard service is active<ul><li data-list-item-id="e91aa18ef8060309b8ab02b27467ddb3d"><pre><code class="language-text-x-trilium-auto">systemctl status AdGuardHome</code></pre></li></ul></li><li data-list-item-id="eeb8f424f3eae4bb102ef11080503bd19">Check failure logs if any<ul><li data-list-item-id="eb6674c289507c1eb4b59544ae1b5cf13"><pre><code class="language-text-x-trilium-auto">journalctl -u AdGuardHome -e --no-pager</code></pre></li><li data-list-item-id="e59ad7a2960a78302fd1281f6b8557eb8">if no logs appear from systemd, check logs directly from the binary<ul><li data-list-item-id="e672620776a5acd061a2490b5faff161b"><pre><code class="language-text-x-trilium-auto">/opt/AdGuardHome/AdGuardHome --check-config -c /opt/AdGuardHome/AdGuardHome.yaml</code></pre></li></ul></li><li data-list-item-id="e9b5cebcec5358b204a5aa3553e1aa21f">in our case last time, the logs said this<ul><li data-list-item-id="e1c19b72364dab9fb55266929bf808522"><pre><code class="language-text-x-trilium-auto">2026/07/29 09:34:43.102794 [fatal] writing config file: write /opt/AdGuardHome/.AdGuardHome.yaml4381677634381549470: no space left on device

root@adguard:~#  
</code></pre></li></ul></li></ul></li><li data-list-item-id="e292577002b77f5309834a232f164f461">Check storage in case of storage issues:<ul><li data-list-item-id="eadfde644402057bbd8561f9f4b91c68c"><pre><code class="language-text-x-trilium-auto">df -h</code></pre></li><li data-list-item-id="ed8d945d06f903afe0467d90b1aea43f3">if we need to clear logs like last time, run this:<ul><li data-list-item-id="e5129c539e75c709b9d6b16f6dbf54b28"><pre><code class="language-text-x-trilium-auto"># Clean systemd journal logs to max 20MB
journalctl --vacuum-size=20M

# Clear apt cache
apt-get clean

# Check if AdGuard query log file is the culprit, again. Last time it was 989MB :(
ls -lh /opt/AdGuardHome/data/</code></pre></li></ul></li><li data-list-item-id="e36bf994d82901dda2e42ed34604ca036">Truncate the querylog if it's the culprit again<ul><li data-list-item-id="eca9e5984b3499e2bb0b30d7cdc8ccaac"><pre><code class="language-text-x-trilium-auto"># Safely empty the query log without breaking file permissions
&gt; /opt/AdGuardHome/data/querylog.json


# Then we restart the service
systemctl restart AdGuardHome

systemctl status AdGuardHome</code></pre></li><li data-list-item-id="e80ee19597c1ae8d0ff77e724894decec">run <code spellcheck="false">df -h</code> again to see if we freed up some space</li></ul></li><li data-list-item-id="e00f95307ac2f00746d97219221d1c0c8">Resize the container with 2 more gigs if storage was the issue<ul><li data-list-item-id="e6899ce9ac7bf0153ad52ba69d49e946e"><pre><code class="language-text-x-trilium-auto">pct resize 103 rootfs +2G</code></pre></li></ul></li></ul></li><li data-list-item-id="ed434d1fe784c21b773adf64bc905afa1">Otherwise, investigate whatever new problem we have</li></ul><p>&nbsp;</p><p><strong>TODO:</strong> Spin up and configure a Grafana&nbsp;<span class="footnote-reference" data-footnote-reference="" data-footnote-index="1" data-footnote-id="l2rfl3c4udc" role="doc-noteref" id="fnrefl2rfl3c4udc"><sup><a href="#fnl2rfl3c4udc">[1]</a></sup></span>instance like Houzair suggested so that i don't have to deal with this again.</p><p>&nbsp;</p><p>&nbsp;</p><ol class="footnote-section footnotes" data-footnote-section="" role="doc-endnotes"><li class="footnote-item" data-footnote-item="" data-footnote-index="1" data-footnote-id="l2rfl3c4udc" role="doc-endnote" id="fnl2rfl3c4udc"><span class="footnote-back-link" data-footnote-back-link="" data-footnote-id="l2rfl3c4udc"><sup><strong><a href="#fnrefl2rfl3c4udc">^</a></strong></sup></span><div class="footnote-content" data-footnote-content=""><p>Grafana: https://grafana.com</p><p>&nbsp;</p></div></li></ol>
